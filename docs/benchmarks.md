## Airport lookup: no label vs unique-constraint index

Without a label the planner must scan every node; with :Airport {iata} it seeks the constraint index.

* naive plan: `ProduceResults > Projection > Filter > AllNodesScan`
* optimised plan: `ProduceResults > Projection > NodeUniqueIndexSeek`

## Search: toLower(name) CONTAINS vs TEXT index on search_text

A function on the property defeats every index; a pre-lowercased property with a TEXT index is used.

* naive plan: `ProduceResults > Projection > Limit > Filter > NodeByLabelScan`
* optimised plan: `ProduceResults > Projection > Limit > NodeIndexContainsScan`

## Airline hubs: scan ROUTE.airlines lists vs SERVES relationships

Modeling choice: SERVES turns a scan of all 37k routes into an index seek + expansion.

* naive plan: `ProduceResults > Top > EagerAggregation > Filter > Expand(All) > CacheProperties > NodeByLabelScan`
* optimised plan: `ProduceResults > Projection > CacheProperties > Top > Projection > Filter > Expand(All) > Distinct`

## Reachability within 3 hops: variable-length path vs ANY SHORTEST

[:ROUTE*1..3] enumerates every path (explodes around hubs); ANY SHORTEST is a BFS, one path per airport.

* naive plan: `ProduceResults > EagerAggregation > Filter > VarLengthExpand(Pruning,BFS,All) > NodeUniqueIndexSeek`
* optimised plan: `ProduceResults > Projection > OrderedAggregation > Sort > Projection > Filter > Projection > StatefulShortestPath(All)`

## Geo search: computed distance on all airports vs POINT index

point.distance on raw lat/lon must be computed for every airport; on `location` the POINT index prunes.

* naive plan: `ProduceResults > Projection > Filter > NodeByLabelScan`
* optimised plan: `ProduceResults > Projection > Filter > NodeIndexSeekByRange`
